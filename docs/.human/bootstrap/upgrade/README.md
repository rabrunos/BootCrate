# Managed bootstrap updates

This is a temporary, local mechanism for files **explicitly** managed during bootstrap. It is not an updater for projects after materialization. The manifest stays ignored at `.local/bootcrate-managed.json` and is removed with bootstrap. It contains a format version, source revision, relative paths and base byte digests, never secrets or absolute machine paths.

After approving which new files BootCrate owns, use `python managed.py init <bootstrap-root> --revision <source-SHA> <path>...`. No pre-existing file becomes managed merely because its name matches. To compare a later source checkout, use `python managed.py preview <bootstrap-root> <new-source-root> [--new-path <approved-new-path>]`; review actions and conflicts. Apply only the reviewed digest with `python managed.py apply <bootstrap-root> <new-source-root> --approved-plan-digest <digest> --revision <new-source-SHA> [--new-path ...]`.

The three-way comparison checks installed base `B`, current bytes `C` and new source `N`. Unchanged local files may update/remove; identical desired files need no write; a local customization stays if upstream did not change; dual edits, deletions, occupied new paths and unknown bases block. Path escapes, symlinks/reparse points, oversized files and a missing bootstrap block. Apply freezes the approved bytes, revalidates each path and manifest under an exclusive local lock, records a transaction journal, and rolls back only writes still matching that transaction. Concurrent owner edits are preserved and leave recovery evidence rather than being overwritten. The tool does not claim to control an unrelated writer outside its lock; reconcile any detected race manually. Materialized products own their files; do not reconstruct this manifest after pruning.

The managed updater uses directory-relative, no-follow operations on POSIX and native directory/file handles on Windows for writes, removals, restore, manifest, journal, lock and cleanup. This blocks path traversal and symlink/junction/reparse redirection at the covered boundaries, including reproduced replacements immediately before mutation; the regressions confirm external bytes remain intact. It also detects source/destination/manifest drift, retains partial-failure recovery evidence, and avoids deleting concurrent owner changes. It is not a sandbox against a hostile process running with the owner's filesystem identity and permissions: on POSIX such a process can move an already-open directory outside the project after descriptor acquisition, and the descriptor still names that inode. Preventing that adversary from changing the checkout requires an OS isolation or permission boundary. Pathname rechecks cannot make directory ancestry atomic against it.
