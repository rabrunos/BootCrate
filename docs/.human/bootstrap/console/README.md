# Optional Project Console

After the owner selects it at the end of intake and approves materialization, copy only `index.html`, `styles.css`, `console.js`, `preset.js` and `execution-profile.js` into the downstream project's `project-console/`. Both resolver files must match their shared counterparts in `../app/`; template validation checks parity. Do not copy Setup, questions, intake, evals or materialization tools. With Console disabled, do not copy this folder at all. Removing it later cannot break the product.

Open `project-console/index.html` as a local file. It imports the stable profile, optional ignored local overrides, the declared version source and history source, and a separately generated delivery preflight per destination. The local version view supports declared `plain` and JSON-pointer `json` readers; other readers show an unsupported message and need native validation. The local check only checks imported inputs, and the history view is not a full changelog parse. It reports requested execution permissions separately from effective permissions, which this import-only page cannot observe. It can download an allowlisted ephemeral snapshot plus small consumption and execution override files for ignored `.local/config/`. It never reads credentials, product source or the full checkout, and cannot silently write files or publish. Consumption uses task/local/project/default precedence; execution uses task/local/safe-default precedence and never derives from autonomy, effort or consumption.

Legacy `project-profile/v2` declares a canonical file but no reader, value path or history source. The Console retains its earlier preview for `VERSION` and a root `version` string in JSON; it reports other v2 sources as unreadable in this view without rejecting the profile or changing the previous view. Optional `CHANGELOG.md` import remains a legacy preview, not a v2 contract requirement. Native validation checks that a v2 canonical source is a safe local file but cannot verify its content without declared metadata; v3 retains the strict declarative version and history checks.

A local profile import is only a UI preview, not a substitute for full schema/finalization validation. Delivery preflight is a preview, not live provider proof. Direct browser write is intentionally absent until a file-mode/permission compatibility spike demonstrates it across the supported browsers; the download plus ordinary file tool is the portable fallback. Validate keyboard order, error/status announcement, zoom/reflow and at least one screen-reader/browser combination before claiming accessibility conformance.
